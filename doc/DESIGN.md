## 1. 設計目標

### 1.1 一句話說明

一個自用的 Chrome 擴充功能：在 HBO Max（台灣版）的播放頁，把**官方英文 CC** 與**官方繁體中文**兩條字幕同時顯示在畫面上（英文在上、中文在下），讓人能邊看動畫邊練英文，不必在兩種字幕之間來回切換。

### 1.2 要驗證的假設 ⭐

> 每條都要寫「怎麼判定」—— 沒有判準的假設驗不了。

| # | 假設 | 如果成立 → | 如果不成立 → | 怎麼判定（看什麼現象） |
|---|---|---|---|---|
| **H1** | 兩條官方字幕軌的 `.vtt` 檔，擴充功能能自己直接取得（不必依賴播放器載入） | 走「讀清單檔→抓兩份」這條路，穩定又不動播放器 | 只能攔截播放器請求，只拿得到使用者目前選的那一條，做不出雙字幕 | 從清單檔解析出兩個網址，`fetch` 回 200 且句數 > 0。**2026-11-11 已成立**（Adventure Time 第 1 季第 19 集：英文 286 句、繁中 248 句） |
| **H2** | 兩條軌**不必逐句配對**，各自依 `currentTime` 顯示目前那一句就夠用 | 實作只需要「某時刻哪些句子在顯示」，不用處理斷句差異 | 要做句子對齊演算法，工作量與出錯面都大很多 | 肉眼看不出明顯錯位。**依據**：繁中 248 句裡只有 14 句與英文起點完全相同，但 246 句與某一英文句在時間上重疊 → 逐句配對本來就做不到、也不需要 |
| **H3** ⚠️ | 疊加層在**全螢幕**與換集之後仍然看得到、位置跟著影片走 | 可以當日常工具用 | 要改掛載策略（例如掛到播放器自己的容器） | 實機：播放 → 按全螢幕 → 兩行字還在；切到下一集 → 兩行字換成新那集的 |
| **H4** | 同樣的做法在其他作品（至少 Rick and Morty）也成立 | 一套邏輯通用 | 要為不同作品寫例外 | 在 Rick and Morty 任一集看到兩行字幕。**尚未驗證** |

> **最可能不成立的是 H3**：疊加層是我們自己掛在頁面上的，播放器怎麼處理全螢幕與換集不在我們控制內。
> 工時主要投放在 H3（掛載與定位），H1、H2 已有實測依據。

### 1.3 明確不驗證什麼

> 這一節比 1.2 更常救命 —— 它防止範圍蔓延，也防止之後被問倒。

- **不做機器翻譯**。第二行一定是 HBO Max 提供的官方字幕軌，沒有就不顯示，不拿 AI 補。
- **不做單字查詢、字典、單字本、字幕下載** —— 那是另一個專案（見 [已排除的方案](#9-已排除的方案)）。
- **不支援 HBO Max 以外的平台**，也不支援手機／電視 App（沒有擴充功能）。
- **不碰影片與音訊串流，不處理 DRM**。只讀字幕文字。
- **目前不上架 Chrome Web Store**。這是自用的「載入未封裝項目」。技術上可以上架，但有版權、服務條款、商標、維護負擔的風險（見 §6），未評估前不做；若要分享，先走「不公開」或「測試人員」，不直接公開上架。

## 2. 結構

### 2.1 全貌

```mermaid
flowchart LR
    A["頁面載入<br/>(擴充功能先注入)"] --> B["觀察資源請求<br/>發現 .mpd 清單檔"]
    B --> C["讀清單檔<br/>找出文字軌"]
    C --> D["依語言挑兩條<br/>上＝英文 下＝繁中"]
    D --> E["各抓一份 .vtt<br/>解析成句子清單"]
    E --> F["每 100ms 讀<br/>video.currentTime"]
    F --> G["找出此刻顯示中的句子<br/>畫在疊加層"]
    G --> F
```

回到起點那條線靠 **`setInterval` 每 100 毫秒一次的 tick** 驅動：讀影片時間、找句子、更新疊加層。換集時播放器會請求新的清單檔，觀察器看到新網址就重新走一遍 B→E。

### 2.2 使用流程

| 階段 | 使用者在做什麼 | 得到什麼 | 預期時長 | 狀態預期 |
|---|---|---|---|---|
| 開始播放 | 在 HBO Max 打開一集，把原生字幕設為「關閉」 | 約 1～3 秒後畫面下方出現兩行字 | 一次性 | 不需要任何額外操作 |
| 觀看中 | 看、聽英文原音，需要時瞄一眼下排中文 | 英文句子與中文意思同時在眼前 | 一集 11～22 分鐘 | 不被打斷 |
| 微調 | 字太大／太小、字幕稍早或稍晚 | 用快捷鍵就地調整，設定會記住 | 偶爾 | 不必離開播放頁 |
| 換集 | 播放下一集 | 兩行字自動換成新那集的 | 自動 | 不需要重新啟動 |

> 「得到什麼」這欄刻意避開泛用答案：這個工具的價值是「**不用在兩種字幕之間切換**」，不是「學得更快」。

## 4. 規格本體

> 數值一律標明是**假值**還是**定案值**。

### 4.1 顯示規則

| 項目 | 規格 | 狀態 |
|---|---|---|
| 上排 | 英文，白色。軌的挑法：語言以 `en` 開頭（實測為 `en-US`、角色 `caption`，即選單裡的「英文 CC」） | 定案 |
| 下排 | 繁體中文，淡黃色（`#ffe27a`）。語言先找 `zh-Hant` 開頭，找不到退到任何 `zh` | 定案 |
| 只有一條軌 | 只顯示有的那一排，另一排整個隱藏（不留空行） | 定案 |
| 兩條都沒有 | 疊加層整個隱藏 | 定案 |
| 同一時刻有多句 | 同一排內以換行串起來，依開始時間排序 | 定案 |
| 作用頁面 | 網址路徑含 `/video/watch/` 才顯示（避免預告片等其他 `<video>` 被蓋上字幕） | 定案 |
| 字級 | 影片高度 × 4% × 字級倍率；下排再放大 10% | **假值**，實機調 |
| 底部留白 | 影片高度的 9%，避開播放器控制列 | **假值**，實機調 |
| 時間對齊 | 直接用 `video.currentTime`，預設偏移 0 毫秒 | 定案 |

### 4.2 快捷鍵（在播放頁按）

| 按鍵 | 作用 | 範圍 |
|---|---|---|
| `Alt`＋`Shift`＋`D` | 開／關疊加層 | |
| `Alt`＋`Shift`＋`↑` / `↓` | 字級倍率 ±0.1 | 0.5～2.0，**假值** |
| `Alt`＋`Shift`＋`[` / `]` | 字幕延後／提早 100 毫秒（`]` 提早） | 無上下限 |

設定存在瀏覽器本機（`hbomax.com` 來源下的 `localStorage`），清除網站資料會回到預設值。

### 4.3 前提：使用者要先關掉原生字幕

HBO Max 的播放器一次只能顯示一條字幕。要用本工具，先在播放器選單的「翻譯字幕」選「關閉」，否則原生那條會和疊加層重疊。

## 6. 與既有約束對照

| 對象 | 約束 | 本專案的處理 |
|---|---|---|
| HBO Max 播放器 | 一次只能顯示一條字幕 | 疊加層自己畫兩條；使用者要關掉原生字幕（§4.3） |
| 內容版權 | 字幕是內容方的著作 | 只在記憶體中處理，不存檔、不進版控（[AGENTS.md](../AGENTS.md) §6.2） |
| DRM | 影音串流有版權保護 | **完全不碰**。我們只讀文字字幕檔 |
| 服務條款 | 擴充功能讀取頁面資料可能不符條款 | **未評估**，僅限個人使用；列入 §8 待決 |
| 公開上架的版權 | 上架＝公開散布一個讀取 HBO Max 字幕的工具，內容方可能提出下架 | 不上架；自用時字幕只在記憶體處理 |
| 商標與命名 | 商店名稱、圖示、說明、截圖不能暗示與 HBO 有關，不能放劇的畫面 | 若上架，名稱用中性描述，截圖用自製假畫面 |
| 商店審核 | 需隱私權政策、權限用途說明；注入 `hbomax.com` 主世界腳本需說明「只讀字幕、不蒐集資料」 | 目前零權限宣告，對審核有利；上架前再準備文件 |
| Claude 桌面 App 內建瀏覽器 | 不支援 DRM，無法播放 HBO Max | 開發時改用實體 Chrome（[踩坑](gotchas/2026-11-11-內建瀏覽器不支援DRM.md)） |

## 9. 已排除的方案

> 設計層的排除。技術層的排除放 [PLAN.md](PLAN.md)「已排除的技術路線」。

| 方案 | 為什麼排除 |
|---|---|
| Language Reactor | 官方只支援 Netflix 與 YouTube，沒有找到 HBO Max 支援的依據 |
| Immersive Translate、HBO Max Dual Subtitles 等 | 第二行是機器翻譯，不是 HBO 官方的繁中字幕，違背本專案要「官方兩條軌」的初衷 |
| 在 HBO 原生字幕上加一條額外字幕（如 Double Subtitles for HBO Max） | 說明沒寫清楚額外那條從哪來；評分偏低；且仍無法確認是官方軌 |
| 先用現成工具試 EasyDualSub | 宣稱會合併官方軌，但很新、用戶少、未實測。**保留為備案**，不是主路線 |
