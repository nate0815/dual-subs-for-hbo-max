# 開發時用竄改猴載入，驗收仍用載入未封裝項目

**選了什麼**
- 開發時用竄改猴轉接腳本 `dev/hds.user.js`：`@require file:///` 依 manifest 的順序讀四個原始檔、`@grant none`、`@run-at document-start`。改完存檔、重新整理 HBO 頁面就生效。
- 驗收（PLAN「驗收方式」）仍用「載入未封裝項目」跑一次。

**沒選什麼、為什麼不選**
- 只用載入未封裝項目：每次改程式要到 `chrome://extensions` 按重新載入再重新整理，反覆調位置、字級時很煩。
- 竄改猴當正式形式：repo 不公開，`@require` 指向 GitHub raw 讀不到；改成單檔要合併四個檔，等於加一道建置。

**如果錯了會怎樣**
- 兩種注入機制不同：竄改猴的 `document-start` 可能比原生內容腳本晚。`PerformanceObserver` 有 `buffered: true` 補得回來，但資源紀錄緩衝區預設只留 250 筆 —— 若晚太多，`.mpd` 會被擠掉，症狀是主控台完全沒有 `[HDS]` 訊息。所以驗收必須回到未封裝。
- 兩者同時開會出現兩層字幕，轉接腳本檔頭有寫。
